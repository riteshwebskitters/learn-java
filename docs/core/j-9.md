# Let's begin J-9.9 — Polymorphism.

We'll use the BankAccount and SavingsAccount classes you've already been working with. No need to start from scratch.
### 1. What is polymorphism?
Polymorphism means one reference type can represent different object types, and the same method call can produce different behaviour depending on the actual object.

Let's understand the problem it solves.

Imagine your banking application supports three account types:
- BankAccount
- SavingsAccount
- CurrentAccount
Each account has a method called calculateInterest().

But each account calculates interest differently.

Without polymorphism, you might end up writing code that checks the account type repeatedly and calls different methods.

Polymorphism lets Java handle this through method overriding.

### 2. First working demonstration

BankAccount.java
```
public class BankAccount {

    public void calculateInterest() {
        System.out.println("Calculating general bank interest");
    }
}
```

SavingsAccount.java
```
public class SavingsAccount extends BankAccount {

    @Override
    public void calculateInterest() {
        System.out.println("Calculating savings interest");
    }
}
```

CurrentAccount.java
```
public class CurrentAccount extends BankAccount {

    @Override
    public void calculateInterest() {
        System.out.println("Calculating current account interest");
    }
}
```

BankDemo.java
```
public class BankDemo {

    public static void main(String[] args) {

        BankAccount account1 = new SavingsAccount();
        BankAccount account2 = new CurrentAccount();
        BankAccount account3 = new BankAccount();

        account1.calculateInterest();
        account2.calculateInterest();
        account3.calculateInterest();
    }
}
```

Output
Calculating savings interest
Calculating current account interest
Calculating general bank interest


Runtime polymorphism
Notice something important:

All three variables have the same reference type: BankAccount.

But they refer to different actual objects.
Reference	Actual object	Executed method
account1	SavingsAccount	Savings implementation
account2	CurrentAccount	Current implementation
account3	BankAccount	Parent implementation

Java decides which overridden implementation to execute at runtime based on the actual object.

This behaviour is also called dynamic method dispatch.
### 3. Why is this useful in real backend development?
Imagine you have a payment-processing system:
Payment payment1 = new CardPayment();
Payment payment2 = new UpiPayment();
Payment payment3 = new WalletPayment();


You could process all three using:
payment1.process();
payment2.process();
payment3.process();


Each payment type supplies its own implementation.

The calling code doesn't need to know the implementation details of every payment type.

That's one of the major benefits of polymorphism.
