J-9.16 — What are annotations?
Annotations provide metadata about your code. They give the compiler, tools, or frameworks additional information about how code should be checked or treated.

You've already used @Override. Let's understand why it matters through a practical example.
1. @Override — preventing accidental mistakes
Suppose we have a parent class:
package corejava.oop;

public class PaymentProcessor {

    public void processPayment() {
        System.out.println("Processing payment");
    }
}


And a child class:
package corejava.oop;

public class UpiPaymentProcessor extends PaymentProcessor {

    @Override
    public void processPayment() {
        System.out.println("Processing UPI payment");
    }
}


Now imagine you accidentally misspell the method:
public class UpiPaymentProcessor extends PaymentProcessor {

    public void processPaymnt() {
        System.out.println("Processing UPI payment");
    }
}


Without @Override, Java accepts this as a separate method. Your parent's processPayment() is never overridden.

But with:
@Override
public void processPaymnt() {
    System.out.println("Processing UPI payment");
}


Compiler catches the mistake
Java reports an error because processPaymnt() doesn't override a method from the parent class.

Important: @Override doesn't perform the overriding. It tells the compiler to verify that you're actually overriding something.
2. @Deprecated — marking old functionality
Imagine your application previously used a method called makePayment(), but you've introduced a better replacement called processPayment().
package corejava.oop;

public class PaymentService {

    @Deprecated(since = "1.0", forRemoval = false)
    public void makePayment() {
        System.out.println("Using old payment method");
    }

    public void processPayment() {
        System.out.println("Using new payment method");
    }
}


When another class calls makePayment(), the compiler or IDE shows a deprecation warning.

This tells developers:
- The method still exists.
- It may continue working.
- Developers should prefer the replacement.
- It may eventually be removed.
3. @SuppressWarnings — suppressing a specific warning
Sometimes you intentionally need to use deprecated functionality, perhaps for backward compatibility.
package corejava.oop;

public class PaymentDemo {

    @SuppressWarnings("deprecation")
    public static void main(String[] args) {

        PaymentService service = new PaymentService();

        service.makePayment();
        service.processPayment();
    }
}


This suppresses the deprecation warning within the annotated method.

Don't use this just to hide warnings. First understand why the warning exists.
