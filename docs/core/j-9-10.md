J-9.10 — Abstract Classes and Interfaces
We'll start with abstract classes.
1. Why do we need an abstract class?
Imagine our banking application supports three account types:
- Savings Account
- Current Account
- Business Account
All accounts should have common functionality, such as:
- Deposit
- Withdraw
- Display balance
But each account type might calculate interest differently.

There is another requirement: we don't want developers accidentally creating a generic BankAccount object. We want them to create a specific account type.

This is where an abstract class becomes useful.
2. Your first abstract class
Consider this demonstration:
package corejava.oop;

public abstract class BankAccount {

    protected double balance;

    public BankAccount(double balance) {
        this.balance = balance;
    }

    public void deposit(double amount) {
        balance += amount;
    }

    public void displayBalance() {
        System.out.println("Balance: " + balance);
    }

    public abstract void calculateInterest();
}


Notice two important things:

First: abstract before the class name
public abstract class BankAccount


This means Java does not allow us to instantiate this class directly.
BankAccount account = new BankAccount(5000); // Compilation error


Second: an abstract method
public abstract void calculateInterest();


Notice that it has no method body.

It declares a requirement: every concrete child class must provide its implementation.
3. Concrete child classes
SAVINGS ACCOUNT
public class SavingsAccount extends BankAccount {

    public SavingsAccount(double balance) {
        super(balance);
    }

    @Override
    public void calculateInterest() {
        System.out.println("Calculating savings interest");
    }
}


CURRENT ACCOUNT
public class CurrentAccount extends BankAccount {

    public CurrentAccount(double balance) {
        super(balance);
    }

    @Override
    public void calculateInterest() {
        System.out.println("Current accounts have no interest");
    }
}


Both children inherit the common functionality, but must implement calculateInterest().
4. How it executes
public class BankAccountDemo {

    public static void main(String[] args) {

        BankAccount savings = new SavingsAccount(5000);
        BankAccount current = new CurrentAccount(10000);

        savings.deposit(1000);

        savings.displayBalance();
        savings.calculateInterest();

        current.displayBalance();
        current.calculateInterest();
    }
}


Expected output:
Balance: 6000.0
Calculating savings interest

Balance: 10000.0
Current accounts have no interest


Notice that we can still use a BankAccount reference even though BankAccount is abstract.

The restriction is on creating a direct BankAccount object, not on using it as a reference type.
