J-9.17 — Custom Annotations (@interface).

Built-in annotations are provided by Java. Custom annotations let us define our own metadata for classes, methods, fields, and other program elements.
1. Why create custom annotations?
Imagine we're building a payment application.

We have several payment methods:
- UPI payment
- Card payment
- Bank transfer
Suppose we want to mark certain methods as requiring an audit review.

We could create a custom annotation called @Auditable.

Instead of writing comments everywhere, we can attach structured metadata to the relevant methods.
2. Create your first custom annotation
Create Auditable.java:
package corejava.oop;

import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Auditable {

    String value();

}


Let's understand the important parts.
Code	Purpose
@interface	Declares a custom annotation
@Retention	Controls how long annotation metadata is retained
RUNTIME	Makes annotation metadata available at runtime
@Target	Controls where the annotation can be applied
ElementType.METHOD	Allows it on methods
String value()	Declares an annotation element

For now, remember two retention policies:
- SOURCE: discarded after compilation.
- CLASS: retained in the compiled class but not necessarily available through runtime reflection.
- RUNTIME: available at runtime through reflection.
3. Use your custom annotation
Create PaymentService.java:
package corejava.oop;

public class PaymentService {

    @Auditable("UPI payment")
    public void processUpiPayment() {
        System.out.println("Processing UPI payment");
    }

    @Auditable("Card payment")
    public void processCardPayment() {
        System.out.println("Processing card payment");
    }

    public void showPaymentStatus() {
        System.out.println("Payment successful");
    }
}


Notice that we attached @Auditable to two methods, but not the third.

The annotation itself doesn't execute any business logic. It simply attaches metadata.
4. Read the annotation at runtime
This is where RetentionPolicy.RUNTIME becomes useful.

Create PaymentDemo.java:
package corejava.oop;

import java.lang.reflect.Method;

public class PaymentDemo {

    public static void main(String[] args) {

        PaymentService service = new PaymentService();

        service.processUpiPayment();
        service.processCardPayment();
        service.showPaymentStatus();

        System.out.println("\n--- Audit Information ---");

        Method[] methods = PaymentService.class.getDeclaredMethods();

        for (Method method : methods) {

            if (method.isAnnotationPresent(Auditable.class)) {

                Auditable audit = method.getAnnotation(Auditable.class);

                System.out.println(
                    method.getName() + " requires audit: " + audit.value()
                );
            }
        }
    }
}


Expected output (method order may vary):
Processing UPI payment
Processing card payment
Payment successful

--- Audit Information ---
processUpiPayment requires audit: UPI payment
processCardPayment requires audit: Card payment


What just happened?
1. getDeclaredMethods() retrieves the methods declared directly in PaymentService.
2. isAnnotationPresent() checks whether a method has our annotation.
3. getAnnotation() retrieves the annotation.
4. audit.value() reads the metadata we supplied.
This is called Reflection. We'll study it in more detail later when it becomes useful.
