# J-9.11 — Interfaces
1. Why do we need interfaces?
Let's use your banking application.

Imagine we introduce these requirements:
- Savings accounts can calculate interest.
- Current accounts can calculate interest.
- Any account that supports online transfers must provide a transfer operation.
- Some accounts may support rewards.
- A payment service should also support online transfers, even though it isn't a bank account.
Notice something?

Different classes may need to follow the same contract without belonging to the same inheritance hierarchy.

That's where interfaces help.
2. First interface demonstration
Create a file named Transferable.java:
package corejava.oop;

public interface Transferable {

    void transfer(double amount);
}


Notice:
- We use interface instead of class.
- We declare a method without its implementation.
- The method is implicitly public abstract.
Now implement it in SavingsAccount:
public class SavingsAccount extends BankAccount implements Transferable {

    public SavingsAccount() {
        super("UNKNOWN");
    }

    @Override
    public void calculateInterest() {
        System.out.println("Calculating savings interest");
    }

    @Override
    public void transfer(double amount) {
        System.out.println("Transferring from savings account: " + amount);
    }
}


The important syntax is:
extends BankAccount implements Transferable


A class can extend one class and implement multiple interfaces.
3. A completely different class can implement the same interface
Consider a payment service:
public class PaymentService implements Transferable {

    @Override
    public void transfer(double amount) {
        System.out.println("Processing online payment: " + amount);
    }
}


PaymentService doesn't extend BankAccount.

Yet it can implement Transferable.

That's the key benefit: an interface defines a capability or contract, not necessarily a family relationship.
4. Interface polymorphism
Now consider:
Transferable savings = new SavingsAccount();
Transferable payment = new PaymentService();

savings.transfer(500);
payment.transfer(1000);


Both references have the type Transferable, but Java executes different implementations.

Expected output:
Transferring from savings account: 500.0
Processing online payment: 1000.0


How the relationship works
Transferable

Interface contract

transfer(double amount)

SavingsAccount

Bank account



PaymentService

Payment service




Both classes fulfill the same interface contract independently.


# J-9.11 — Next: Interface methods
There are a few important features we need to understand.
A. Abstract methods
public interface Printable {
    void print();
}


By default, this method is public abstract.
B. Default methods
Interfaces can also provide an implementation:
public interface Printable {

    void print();

    default void printStatus() {
        System.out.println("Ready to print");
    }
}


A class implementing Printable inherits printStatus() and can use it without overriding it.
C. Static methods
Interfaces can contain static methods:
public interface Printable {

    static void showVersion() {
        System.out.println("Printable API v1");
    }
}


Call it using the interface name:
Printable.showVersion();


D. Interface fields
Consider:
public interface PaymentRules {
    double MAX_TRANSFER_LIMIT = 100000;
}


Interface fields are implicitly:
- public
- static
- final
So this is effectively:
public static final double MAX_TRANSFER_LIMIT = 100000;


They are constants, not instance variables.
