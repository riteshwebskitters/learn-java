# J-12.8 — TreeMap


Now let's look at the third important Map implementation.

Imagine your transaction records need to be displayed in ascending order by transaction ID.
- HashMap: no guaranteed order.
- LinkedHashMap: insertion order.
- TreeMap: sorted by key.
How the three Maps differ
HashMap

Insertion order: TXN1005, TXN1002, TXN1008, TXN1001

{TXN1005, TXN1002, TXN1008, TXN1001}


LinkedHashMap

Preserves insertion order

{TXN1005, TXN1002, TXN1008, TXN1001}


TreeMap

Sorts keys naturally

{TXN1001, TXN1002, TXN1005, TXN1008}


3. Working example
package corejava.engineering.collection;

import java.util.Map;
import java.util.TreeMap;

public class TransactionSortedMap {
    public static void main(String[] args) {

        Map<String, Integer> transactions = new TreeMap<>();

        transactions.put("TXN1005", 5000);
        transactions.put("TXN1002", 2500);
        transactions.put("TXN1008", 8000);
        transactions.put("TXN1001", 1500);

        System.out.println(transactions);
    }
}


Output:
{TXN1001=1500, TXN1002=2500, TXN1005=5000, TXN1008=8000}


Notice that TreeMap sorts by key, not by value.



Collections Framework — Map comparison
Let's consolidate what we've learned.
Map	Ordering	Duplicate keys	Typical performance
HashMap	No guarantee	No	O(1) average
LinkedHashMap	Insertion order	No	O(1) average
TreeMap	Sorted keys	No	O(log n)

Remember:
- HashMap → fast lookup.
- LinkedHashMap → predictable insertion order.
- TreeMap → sorted keys.
