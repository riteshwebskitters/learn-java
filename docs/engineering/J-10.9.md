J-10.9 — Try-with-resources
This is an important Java feature for backend development because applications frequently work with:
- Files
- Database connections
- Database statements and result sets
- Network connections
- Other resources that must be closed
1. The problem it solves
Imagine opening a file:
BufferedReader reader = new BufferedReader(
    new FileReader("transactions.txt")
);


After using it, we need to close it:
reader.close();


But what happens if an exception occurs before close() executes?

The resource might remain open.

Previously, we learned about finally. We could use it to close resources, but Java provides a cleaner approach: try-with-resources.
2. First demonstration
Create TryWithResourcesDemo.java inside your exceptions package.
package corejava.engineering.exceptions;

import java.io.BufferedReader;
import java.io.IOException;
import java.io.StringReader;

public class TryWithResourcesDemo {

    public static void main(String[] args) {

        try (BufferedReader reader = new BufferedReader(
                new StringReader("TXN1001\nTXN1002\nTXN1003"))) {

            String transaction;

            while ((transaction = reader.readLine()) != null) {
                System.out.println("Processing: " + transaction);
            }

        } catch (IOException exception) {
            System.out.println("Reading failed: " + exception.getMessage());
        }

        System.out.println("Transaction processing completed");
    }
}


Expected output:
Processing: TXN1001
Processing: TXN1002
Processing: TXN1003
Transaction processing completed


3. Understand the syntax
Look carefully at this:
try (BufferedReader reader = new BufferedReader(...)) {


Previously, we wrote:
try {
    // Operations
}


Now we're declaring a resource inside the parentheses after try.

Java automatically closes that resource when the try block finishes, whether it finishes normally or because an exception occurs.
Execution lifecycle
1. Open the resource.
2. Execute the try block.
3. Automatically close the resource.
4. Execute the matching catch block if an exception occurred.
5. Continue with the next statement.

The resource must implement AutoCloseable (or its subinterface Closeable) for this feature to work.

BufferedReader supports it.
