# J-12.9 — Queue
So far, we've stored transactions in lists, sets, and maps.

Now let's consider a payment-processing scenario.

Imagine five transactions arrive:
TXN1001
TXN1002
TXN1003
TXN1004
TXN1005


The payment processor should process them in the order they arrive.

This is called FIFO — First In, First Out.
Transaction processing queue
First in
Processed first

TXN1001

TXN1002

TXN1001 leaves the queue first.

Basic Queue implementation
Java provides the Queue interface.
import java.util.LinkedList;
import java.util.Queue;

public class TransactionQueue {

    public static void main(String[] args) {

        Queue<String> transactions = new LinkedList<>();

        transactions.offer("TXN1001");
        transactions.offer("TXN1002");
        transactions.offer("TXN1003");

        System.out.println(transactions);

        System.out.println("Next transaction: " + transactions.peek());

        System.out.println("Processing: " + transactions.poll());

        System.out.println("Remaining: " + transactions);
    }
}


Output:
[TXN1001, TXN1002, TXN1003]
Next transaction: TXN1001
Processing: TXN1001
Remaining: [TXN1002, TXN1003]


Three important Queue methods
Method	Purpose
offer()	Adds an element
peek()	Reads the first element without removing it
poll()	Retrieves and removes the first element

There are also add(), element(), and remove(), which have different behaviours when the queue is empty or insertion fails.
