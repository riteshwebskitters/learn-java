J-10.2 — Multiple catch blocks
So far, we've handled one exception type:
catch (ArithmeticException exception) {
    System.out.println("Transaction failed");
}


But real applications can encounter different types of errors.

Imagine a banking application that processes a withdrawal:
- Division by zero → ArithmeticException
- Accessing an invalid array index → ArrayIndexOutOfBoundsException
- Converting invalid text into a number → NumberFormatException
We can handle different exceptions separately using multiple catch blocks.
Demonstration
Create MultipleCatchDemo.java in your exceptions package.
package corejava.engineering.exceptions;

public class MultipleCatchDemo {

    public static void main(String[] args) {

        try {
            String transactionAmount = "ABC";

            int amount = Integer.parseInt(transactionAmount);

            int balance = 5000;
            int remainingBalance = balance / amount;

            int[] transactions = {1000, 2000, 3000};

            System.out.println(transactions[5]);
            System.out.println("Remaining balance: " + remainingBalance);

        } catch (ArithmeticException exception) {

            System.out.println("Arithmetic error: " + exception.getMessage());

        } catch (NumberFormatException exception) {

            System.out.println("Invalid transaction amount: " + exception.getMessage());

        } catch (ArrayIndexOutOfBoundsException exception) {

            System.out.println("Invalid transaction index: " + exception.getMessage());
        }

        System.out.println("Banking application continues running");
    }
}


Expected output:
Invalid transaction amount: For input string: "ABC"
Banking application continues running


Understand the execution
Look at this line:
int amount = Integer.parseInt(transactionAmount);


The value "ABC" cannot be converted into an integer.

Therefore:
1. Java throws NumberFormatException.
2. The remaining statements inside try are skipped.
3. Java checks the catch blocks.
4. The matching NumberFormatException block executes.
5. Execution continues after the entire try-catch structure.
Important: Only the first exception encountered is handled during this execution. The other catch blocks don't execute just because they exist.
A rule you must understand
Catch blocks are checked from top to bottom.

For example, this is incorrect:
try {
    // Some code
} catch (Exception exception) {
    System.out.println("General error");
} catch (ArithmeticException exception) {
    System.out.println("Arithmetic error");
}


Why? Because ArithmeticException is already covered by the earlier, broader Exception catch block. The second catch is unreachable.

Put specific exceptions before general exceptions.
