J-11.3 — Generics in Java
Generics are important because they let us write reusable, type-safe code. You'll use them extensively with Java Collections, Spring Boot repositories, API responses, and service-layer code.
1. The problem Generics solve
Imagine we want to store a transaction amount.

Without generics, we might use Object:
Object transactionAmount = 5000;

Integer amount = (Integer) transactionAmount;

System.out.println(amount);


This works, but there's a problem: Object can hold almost anything.
Object transactionAmount = "FIVE THOUSAND";

Integer amount = (Integer) transactionAmount;


This compiles, but fails at runtime with a ClassCastException.

Generics help catch this kind of type mismatch at compile time.
2. Your first generic type
Consider:
public class Transaction<T> {

    private T transactionData;

    public Transaction(T transactionData) {
        this.transactionData = transactionData;
    }

    public T getTransactionData() {
        return transactionData;
    }
}


Let's understand the important parts:
Code	Meaning
T	A type parameter
Transaction<T>	A generic class
private T transactionData	Data whose type is decided when the object is created
Transaction(T transactionData)	Constructor accepts that chosen type
public T getTransactionData()	Returns the same chosen type

T is a placeholder, not a special Java keyword. We could call it Data, but T is the common convention for a type parameter.
3. Using the generic class
Transaction<Integer> payment = new Transaction<>(5000);

Integer amount = payment.getTransactionData();

System.out.println(amount);


Here, T becomes Integer.

We can reuse the same class with another type:
Transaction<String> transactionStatus =
        new Transaction<>("SUCCESS");

String status = transactionStatus.getTransactionData();

System.out.println(status);


Now T becomes String.

The key benefit: Java checks the type for us. A Transaction<Integer> cannot accept a String as its transaction data.
