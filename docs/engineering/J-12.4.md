# J-12.4 — LinkedHashSet
Now let's understand another Set implementation.
1. Why LinkedHashSet?
Remember the problem with HashSet?

It does not guarantee insertion order.

Suppose you insert:
TXN1001
TXN1002
TXN1003
TXN1004


You might want to maintain that insertion order while still preventing duplicates.

That's where LinkedHashSet comes in.








cleverence.com


LinkedHashSet:
- Prevents duplicates.
- Maintains insertion order.
- Provides efficient average membership checking.
2. Example
package corejava.engineering.collection;

import java.util.LinkedHashSet;
import java.util.Set;

public class TransactionOrderRegistry {

    public static void main(String[] args) {

        Set<String> transactionIds = new LinkedHashSet<>();

        transactionIds.add("TXN1001");
        transactionIds.add("TXN1002");
        transactionIds.add("TXN1003");
        transactionIds.add("TXN1001");
        transactionIds.add("TXN1004");

        System.out.println(transactionIds);
    }
}


Output:
[TXN1001, TXN1002, TXN1003, TXN1004]


Notice that the duplicate TXN1001 is ignored, and insertion order is maintained.
3. Compare the three implementations
Feature	HashSet	LinkedHashSet	TreeSet
Duplicates	No	No	No
Insertion order	No guarantee	Yes	No
Sorted order	No	No	Yes
Average basic operations	O(1)	O(1)	O(log n)
