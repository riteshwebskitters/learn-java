J-10.7 — Exception propagation
This is particularly important for backend development.

Imagine a payment request travels through multiple layers:
Controller

Receives the payment request

Payment Service

Processes payment logic

Account Service

Checks account balance

Exception occurs

Insufficient balance

Exception travels back up the call stack until a matching handler catches it.
This movement is called exception propagation.
1. Demonstration
Create ExceptionPropagationDemo.java.
package corejava.engineering.exceptions;

public class ExceptionPropagationDemo {

    public static void accountService() {

        System.out.println("Account service started");

        int balance = 5000;
        int withdrawalAmount = 7000;

        if (withdrawalAmount > balance) {
            throw new IllegalArgumentException("Insufficient balance");
        }

        System.out.println("Account service completed");
    }

    public static void paymentService() {

        System.out.println("Payment service started");

        accountService();

        System.out.println("Payment service completed");
    }

    public static void main(String[] args) {

        try {
            System.out.println("Payment request received");

            paymentService();

        } catch (IllegalArgumentException exception) {

            System.out.println("Payment failed: " + exception.getMessage());
        }

        System.out.println("Application continues running");
    }
}


Expected output:
Payment request received
Payment service started
Account service started
Payment failed: Insufficient balance
Application continues running


2. Understand what happened
1. main() calls paymentService().
2. paymentService() calls accountService().
3. accountService() throws IllegalArgumentException.
4. accountService() has no matching catch block.
5. paymentService() has no matching catch block.
6. The exception propagates back to main().
7. main() catches it.
8. Execution continues after the catch block.
Notice that these messages never appear:
Account service completed
Payment service completed


Why? Because the exception interrupted normal execution before those statements could run.
