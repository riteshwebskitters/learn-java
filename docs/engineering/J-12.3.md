# J-12.3 — Set Interface and HashSet
Now let's learn another important collection type.
1. Why do we need Set?
Imagine a payment system receiving transaction IDs:
TXN1001
TXN1002
TXN1003
TXN1001
TXN1004


Should the system store TXN1001 twice in a collection intended to contain unique IDs?

No. This is where Set becomes useful.

A Set:
- Does not allow duplicate elements.
- Does not provide index-based access.
- Has different implementations with different ordering behaviours.
2. Understanding HashSet

HashSet uses hashing internally to manage unique elements.

Example:
package corejava.engineering.collection;

import java.util.HashSet;
import java.util.Set;

public class TransactionIdRegistry {

    public static void main(String[] args) {

        Set<String> transactionIds = new HashSet<>();

        transactionIds.add("TXN1001");
        transactionIds.add("TXN1002");
        transactionIds.add("TXN1003");
        transactionIds.add("TXN1001");

        System.out.println(transactionIds);
        System.out.println("Total unique transactions: " + transactionIds.size());
    }
}


The size will be 3, because the duplicate TXN1001 is not inserted a second time.

Important: HashSet does not guarantee insertion order. Your printed elements may appear in a different order.
3. Important HashSet methods
Method	Purpose
add()	Add an element
remove()	Remove an element
contains()	Check whether an element exists
size()	Get the number of unique elements
isEmpty()	Check whether empty
clear()	Remove all elements

One useful detail: add() returns a boolean.
- true → element was added.
- false → element already existed.
