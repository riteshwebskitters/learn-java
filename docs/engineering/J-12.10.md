# J-12.10 — Deque (Double-Ended Queue)

Now let's extend the queue concept.

A normal FIFO queue primarily processes elements from the front and adds them at the rear.

A Deque allows insertion and removal from both ends.
Deque illustration
Front
Rear

TXN1001

TXN1002

TXN1003


Remove / add

Add / remove


Basic implementation
import java.util.ArrayDeque;
import java.util.Deque;

public class TransactionDeque {

    public static void main(String[] args) {

        Deque<String> transactions = new ArrayDeque<>();

        transactions.offerLast("TXN1001");
        transactions.offerLast("TXN1002");
        transactions.offerLast("TXN1003");

        transactions.offerFirst("TXN1000");

        System.out.println(transactions);

        System.out.println("First: " + transactions.peekFirst());
        System.out.println("Last: " + transactions.peekLast());

        System.out.println("Remove First: " + transactions.pollFirst());
        System.out.println("Remove Last: " + transactions.pollLast());

        System.out.println("Final: " + transactions);
    }
}


Output:
[TXN1000, TXN1001, TXN1002, TXN1003]
First: TXN1000
Last: TXN1003
Remove First: TXN1000
Remove Last: TXN1003
Final: [TXN1001, TXN1002]


Important Deque methods
Front	Rear
offerFirst()	offerLast()
pollFirst()	pollLast()
peekFirst()	peekLast()

ArrayDeque is generally a good choice for an in-memory queue or stack. It doesn't allow null elements.



## Understand how Deque behaves as Queue and Stack
This is worth remembering.

Deque as Queue — FIFO
transactions.offerLast("TXN1001");
transactions.pollFirst();


Add at the rear, remove from the front.

Deque as Stack — LIFO
transactions.push("TXN1001");
transactions.push("TXN1002");

System.out.println(transactions.pop());


Output:
TXN1002


The last inserted element is removed first.

This is why Deque is often preferred over the legacy Stack class for stack operations.
