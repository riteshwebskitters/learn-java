J-10.4 — throw vs throws.

These two keywords are important because they allow us to define how invalid operations are reported and where exceptions are handled.
1. throw — explicitly throw an exception
Suppose a customer tries to withdraw ₹15,000 when their balance is only ₹10,000.

Java doesn't automatically know this violates your banking business rule. We need to validate it and explicitly throw an exception.

Example:
package corejava.engineering.exceptions;

public class ThrowDemo {

    public static void main(String[] args) {

        int balance = 10000;
        int withdrawalAmount = 15000;

        if (withdrawalAmount > balance) {
            throw new IllegalArgumentException(
                "Insufficient account balance"
            );
        }

        int remainingBalance = balance - withdrawalAmount;

        System.out.println("Remaining balance: " + remainingBalance);
    }
}


Output:
Exception in thread "main" java.lang.IllegalArgumentException:
Insufficient account balance


Here:
- throw explicitly creates and throws an exception.
- IllegalArgumentException is an unchecked exception.
- Execution stops at the throw statement unless the exception is caught somewhere.
Important: This is business validation. We are choosing to represent an invalid argument as an exception.
2. throws — declare that a method may throw an exception
Now imagine a method responsible for processing withdrawals.

Instead of handling an exception inside that method, we can declare that the caller must deal with it.
package corejava.engineering.exceptions;

public class ThrowsDemo {

    public static void withdraw(int balance, int amount) {

        if (amount > balance) {
            throw new IllegalArgumentException("Insufficient balance");
        }

        System.out.println("Withdrawal successful");
        System.out.println("Remaining balance: " + (balance - amount));
    }

    public static void main(String[] args) {

        try {
            withdraw(10000, 15000);

        } catch (IllegalArgumentException exception) {
            System.out.println("Transaction failed: " + exception.getMessage());
        }
    }
}


Notice that this method uses throw, but not throws.

Why?

Because IllegalArgumentException is unchecked. Java does not require us to declare it in the method signature.
3. A real example of throws
Let's use a checked exception: InterruptedException.
package corejava.engineering.exceptions;

public class ThrowsCheckedDemo {

    public static void processTransaction() throws InterruptedException {

        System.out.println("Processing transaction...");

        Thread.sleep(2000);

        System.out.println("Transaction completed");
    }

    public static void main(String[] args) {

        try {
            processTransaction();

        } catch (InterruptedException exception) {
            System.out.println("Transaction processing interrupted");
        }
    }
}


Here:
public static void processTransaction() throws InterruptedException


means the method declares that it may throw InterruptedException.

Because it is checked, the caller must either:
- Handle it using try-catch, or
- Declare it using throws and pass responsibility to its caller.
4. Understand the difference
throw	throws
Actually throws an exception	Declares possible exceptions
Used inside a method or block	Used in method signature
Followed by an exception object	Followed by exception class names
Throws one exception object at a time	Can declare multiple exception types

Remember this:
throw new IllegalArgumentException("Invalid amount");


Versus:
public void processPayment() throws InterruptedException
