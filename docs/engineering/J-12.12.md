# J-12.12 — Comparable and Comparator

This is an important topic because backend applications frequently need to sort records based on different business requirements.

Imagine you have these transactions:
Transaction ID	Amount
TXN1005	5000
TXN1002	1200
TXN1008	8000
TXN1001	2500

You might want to sort them by:
- Transaction ID.
- Transaction amount.
- Transaction amount in descending order.
- Transaction date.
Java provides two interfaces for defining sorting behaviour.
1. Comparable — Natural ordering
Comparable defines the natural/default sorting order of a class.

For example, suppose you have a Transaction class.
package corejava.engineering.collection;

public class Transaction implements Comparable<Transaction> {

    private String transactionId;
    private int amount;

    public Transaction(String transactionId, int amount) {
        this.transactionId = transactionId;
        this.amount = amount;
    }

    public String getTransactionId() {
        return transactionId;
    }

    public int getAmount() {
        return amount;
    }

    @Override
    public int compareTo(Transaction other) {
        return Integer.compare(this.amount, other.amount);
    }

    @Override
    public String toString() {
        return transactionId + " : " + amount;
    }
}


Notice this method:
@Override
public int compareTo(Transaction other) {
    return Integer.compare(this.amount, other.amount);
}


It defines the natural ordering based on transaction amount, ascending.

The comparison result means:
Result	Meaning
Negative	Current object comes before the other
Zero	Both are equal for this comparison
Positive	Current object comes after the other

We use Integer.compare() instead of subtracting values because subtraction can overflow for extreme integer values.
Sorting with Comparable
List<Transaction> transactions = new ArrayList<>();

transactions.add(new Transaction("TXN1005", 5000));
transactions.add(new Transaction("TXN1002", 1200));
transactions.add(new Transaction("TXN1008", 8000));
transactions.add(new Transaction("TXN1001", 2500));

Collections.sort(transactions);

System.out.println(transactions);


Output:
[TXN1002 : 1200, TXN1001 : 2500, TXN1005 : 5000, TXN1008 : 8000]


Collections.sort() uses the natural ordering defined by compareTo().
2. Comparator — Custom ordering
Now imagine the business requirement changes.

You want to sort the same transactions by amount in descending order.

But you don't want to change the natural ordering inside the Transaction class.

That's where Comparator comes in.
Comparator<Transaction> amountDescending = (t1, t2) ->
        Integer.compare(t2.getAmount(), t1.getAmount());

transactions.sort(amountDescending);


Output:
[TXN1008 : 8000, TXN1005 : 5000, TXN1001 : 2500, TXN1002 : 1200]


Notice the difference:
- Comparable defines the class's natural ordering.
- Comparator defines an alternative/custom ordering externally.
Comparable vs Comparator
Comparable
Inside the class

Defines the natural ordering using compareTo().


Comparator
Outside the class

Defines custom ordering using compare().
