# J-12.7 — LinkedHashMap

Now let's understand why LinkedHashMap exists.

Imagine you are displaying a transaction history in an admin dashboard.

You want:
- Unique transaction IDs.
- Fast lookup by transaction ID.
- Transactions displayed in the order they were inserted.
HashMap doesn't guarantee that display order. LinkedHashMap maintains insertion order by default.
1. Example
package corejava.engineering.collection;

import java.util.LinkedHashMap;
import java.util.Map;

public class TransactionHistoryMap {
    public static void main(String[] args) {

        Map<String, Integer> transactions = new LinkedHashMap<>();

        transactions.put("TXN1003", 1200);
        transactions.put("TXN1001", 2500);
        transactions.put("TXN1002", 4500);
        transactions.put("TXN1004", 3500);

        System.out.println(transactions);
    }
}


Output:
{
    TXN1003=1200,
    TXN1001=2500,
    TXN1002=4500,
    TXN1004=3500
}


Notice that the entries remain in insertion order, not alphabetical order.
2. Important behaviour: Updating an existing key
Consider:
transactions.put("TXN1003", 9000);


The value changes, but the entry stays in its original position.

Output:
{
    TXN1003=9000,
    TXN1001=2500,
    TXN1002=4500,
    TXN1004=3500
}
