J-11.2 — Wrapper Class Utility Methods
Wrapper classes aren't just containers for primitive values. They also provide useful static methods for conversion, comparison, and validation.

These methods are particularly useful when processing API input, transaction amounts, and configuration values.
1. parseInt() vs valueOf()
You've already used both concepts.
String amount = "2500";

// Returns primitive int
int parsedAmount = Integer.parseInt(amount);

// Returns Integer object
Integer wrappedAmount = Integer.valueOf(amount);


Method	Return type	Purpose
Integer.parseInt()	int	Convert String into primitive
Integer.valueOf()	Integer	Convert String into wrapper object

2. Other useful wrapper methods
A. compare()

Compares two integer values.
int result = Integer.compare(5000, 3000);

System.out.println(result);


Output:
1


Results:
- -1 when the first value is smaller.
- 0 when both values are equal.
- 1 when the first value is greater.
B. max() and min()
int highest = Integer.max(5000, 8000);
int lowest = Integer.min(5000, 8000);

System.out.println(highest); // 8000
System.out.println(lowest);  // 5000


C. toString()

Converts an integer into a String.
int amount = 5000;

String transaction = Integer.toString(amount);

System.out.println(transaction);


D. isDigit()

Useful when examining individual characters.
char value = '5';

System.out.println(Character.isDigit(value));


Output:
true



3. Important concept — Null unboxing
This is particularly important.

Consider:
Integer balance = null;

int accountBalance = balance;


What happens?
Runtime exception
Java throws:
NullPointerException


Why?

Because Integer is an object reference, and it currently refers to nothing.

When Java tries to convert it into primitive int, it needs to extract an integer value. It cannot extract a value from null.

This operation is called unboxing.
How should we handle it?
Integer balance = null;

int accountBalance = balance != null ? balance : 0;

System.out.println(accountBalance);


Output:
0


This is a simple example of defensive programming.

In a real banking application, don't automatically treat every missing balance as zero. Depending on the business rules, you may need to reject the missing value instead.
